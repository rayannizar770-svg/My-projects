# get_next_line

## Description

**get_next_line** is a 42 core curriculum project that implements a function reading a text file (or any file descriptor, including standard input) one line at a time, across repeated calls, without reading the whole file at once.

## Algorithm

The function relies on a `static` variable (`saved`) to persist the unread remainder of the file between successive calls, since no global variables are allowed. On each call:

1. **`read_to_buffer`** reads from the file descriptor in chunks of `BUFFER_SIZE` bytes, joining each chunk onto `saved`, until a `\n` is found in `saved` or `read` reaches the end of the file.
2. **`extract_line`** isolates the first line from `saved` — from its start up to and including the `\n`, or the whole remainder if no `\n` is present (end of file).
3. **`update_saved`** keeps everything after that `\n` as the new `saved`, ready for the next call, or frees it and returns `NULL` once nothing is left.

This buffer-by-buffer approach reads only as much as needed at each call, so it works correctly and efficiently regardless of `BUFFER_SIZE` (tested with 1, 42, 9999 and the default value).

## Instructions

### Compilation

The project must be compiled with the caller's own files, specifying a buffer size:

```bash
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c your_file.c -o your_program
```

It also compiles without `-D BUFFER_SIZE`, falling back to a default value defined in the header.
